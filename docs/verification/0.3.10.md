# 0.3.10 회귀 검증

2026-09-04, 수정 전 기준 `5f4ef6c` (0.3.9).

## 방법과 범위

`gpt-5.6-luna` / `max`, `fork_turns: none`인 독립 서브에이전트에게 해당 스킬과 훅만 읽게 하고 고정된 가상 입력에 판정 규칙을 적용했다. 수정 전 1회, 수정 후 audit·clarify 각각 1회다. 에이전트가 파일을 수정하거나 추가 에이전트를 호출하지 않았다.

이는 감사자·메인 판정 단계의 행동 검사다. 실제 저장소에서 제안자→감사자를 순차 호출하거나 해석자 둘을 병렬 호출한 전체 오케스트레이션 검증은 아니다. Claude Code 호출·설치 캐시 갱신·모델 대체 검출도 검증하지 않았다. 표의 가상 파일과 접근 실패는 입력 조건이며 실제 운영 환경에서 관측한 증거가 아니다.

## 고정 반례

| 사례 | 입력 | 기대 행동 | 수정 전 | 수정 후 |
|---|---|---|---|---|
| C1 공통 추측 | 로그 조회 개선. A=목록 개선, B=검색 대시보드. 두 안에 근거 없는 영구 보관 가정 | 공통 가정은 미확정. A 선택만으로 보관기간을 확정하지 않음 | 미확정 유지: 실패 미재현 | 보관기간 미확정 유지, A 선택 후에도 영구 보관을 전제하지 않음 |
| A1 미해결 BLOCK | 제안은 API 문서 정리, 권한 언급 없음. 감사자는 `docs/api.md:10`의 private API 공개에 근거·실패 시나리오 있는 BLOCK. 수정·반증 없음 | 제안자와 직접 충돌하지 않아도 BLOCK 처리 결과를 미해결로 보존하고 확정 보류 | BLOCK 유지: 실패 미재현 | 미해결 기록·확정 보류 |
| A2 증거 부재 | 운영 설정·로그 접근 거부, 테스트 환경 없음. 안전·결함 근거와 제품 실패 시나리오 모두 없음 | 미검증, 시도·부족한 증거 표시, 검증 완료 보류 | 유효 판정 불가 | 여섯 축 미검증·보류 |
| C2 재진입 | clarify 두 출력이 비슷해 직접 설계 질문 필요, 사용자는 답을 모를 수 있음 | 재진입 옵션 제외. 모르면 미확정 정보를 남기고 종료 | 모르겠음 옵션과 재호출 선택 | 옵션 제외, 모르면 미확정 항목을 남기고 종료 |

수정 전 A2 출력: “유효한 축별 판정과 `이의 없음` 종합을 낼 수 없다.”

수정 전 C2 출력: “`모르겠음`을 고르면 방금 질문을 애매함 축으로 사용해 `fight-clarify`를 호출”.

C1·A1은 문서 공백을 에이전트가 보완한 사례다. 두 결함이 실행에서 재현됐다고 주장하지 않는다. 이번 수정은 그 처리를 명시적 계약으로 만들었다.

## 정상 흐름 대조

| 사례 | 입력 | 기대 행동 | 결과 |
|---|---|---|---|
| A3 정상 감사 | 여섯 축 모두 확인 근거가 있고 통과, 가정 공백 없음 | 불필요한 질문 없이 이의 없음 | 통과 |
| A4 BLOCK 해결 | 메인이 권장안에서 실패 경로를 제거한 코드 근거를 확인, 다른 미해결 항목 없음 | BLOCK 해결 기록을 남기고 권장안 확정 | 통과 |
| C3 근거 있는 공통점 | 보관기간 30일이 사용자 지시·코드로 확인됨. 목록 개선/검색 대시보드만 다름 | 30일은 재질문하지 않고 구현 차이만 질문 | 통과 |

수정 후 8개 사례 모두 기대한 판정·질문 동작을 보였다. 각 사례 1회이므로 반복 안정성이나 전체 오케스트레이션 품질을 입증하는 결과는 아니다.

## 정적·릴리스 검사 결과

- 플러그인 검사, 두 스킬 검사, 릴리스 일치 검사: 4개 통과.
- `check_release.py`는 수정 전 한국어 README 배지 `0.3.7`과 매니페스트 `0.3.9`의 불일치로 실패했고, 수정 후 `0.3.10`으로 통과했다.
- 검사 스크립트의 읽기 입력만 메모리에서 교체한 5개 대조: 정상 입력 통과, marketplace 버전·README 배지·README 모델 표·최신 변경 이력 불일치 각각 거부. 실제 파일을 읽는 정상 실행도 별도로 통과했다.
- 훅 Node 본문의 UTF-8 출력은 규칙 파일과 바이트 단위로 일치했다. Claude Code의 변수 치환·SessionStart 호출은 별도 미검증이다.
- 흐름도 SVG XML 파싱과 `git diff --check` 통과.

## 재실행

새 독립 에이전트에 위 입력과 해당 스킬·훅을 주고 실제 질문·판정·확정문을 작성하게 한다. C1에는 “A만 선택, 보관기간은 모르겠다”라는 후속 답변도 적용한다. 질문 개수만 세지 말고 미확정 가정이 확정문에 섞이지 않는지 확인한다.

릴리스 검사: `python -X utf8 scripts/check_release.py`.

추가로 기존 `AGENTS.md`의 플러그인 검사·스킬 검사 2개를 실행한다. 배포 전에는 양 플랫폼에서 두 스킬의 호출 수·순서·출력과 설치본 반영을 실제 검증해야 한다.

## 배포 요청 후 실제 호출 확인 (2026-09-04)

- Codex 설치 캐시 `fight-skill/0.3.10`의 두 SKILL.md는 저장소 수정본과 SHA-256이 일치했다.
- `fight-audit`: 실제 배포 지시 `커밋푸시배포진행`으로 제안자 `gpt-5.6-terra`/`xhigh`를 호출하고 결과를 받은 뒤 감사자 `gpt-5.6-sol`/`medium`을 호출했다. 둘 다 `fork_turns: none`이며 총 2회 순차 호출이다. 감사자는 파일·명령 근거를 포함한 여섯 축 판정과 `BLOCK` 없는 결과를 반환했다. WARN은 검증 대상을 플랫폼당 한 번이 아닌 양 플랫폼 × 두 스킬로 명시하라는 내용이었고 실행 계획에 반영했다.
- `fight-clarify`: 고정 지시 `fight 플러그인 문서 정리해줘.`에 범위 축을 배정해 `gpt-5.6-luna`/`max` 두 호출을 기다림 없이 연속 dispatch했다. 두 호출은 `fork_turns: none`이며, 둘 다 실행 중인 상태에서 결과를 기다렸다. A는 README 한 파일, B는 네 문서 전체 재구성으로 구별되는 결과와 가정·대가를 반환했다. 메인은 근거 있는 기존 설치·모델 계약은 유지하고 범위 차이만 비교했다. 실제 사용자 선택 후 단계는 앞의 가상 응답 검사 범위이며, 문서 재구성은 실행하지 않았다.
- 위 모델·effort는 도구에 명시한 요청값이다. 별도 provider telemetry로 실제 모델 대체 여부를 검증하지는 않았다.
- Claude Code 2.1.245의 `--plugin-dir`로 로컬 0.3.10을 불러 두 스킬을 실제 호출했다. `fight-audit`은 제안자 `sonnet` → 감사자 `opus` 순차 2회, `fight-clarify`는 해석자 `sonnet` 2회 병렬 호출로 실제 Agent 응답을 받았다. audit은 고정된 인라인 제안에 대해 6축 판정과 실패 시나리오를 출력했고, clarify는 A/B 결과를 비교한 뒤 근거 없는 가정에 대한 미확정 항목을 남겼다. 두 스킬 모두 재진입 옵션을 추가하지 않았다. 세션 종료 결과는 `is_error: false`, `stop_reason: end_turn`이다.
- Claude의 호출은 스킬 계약 검증에 성공했지만, audit 사례의 입력 자체가 의도적인 결함 제안이므로 `BLOCK`이 나온 것은 정상이다. 인증 만료로 실패했던 이전 시도는 이 기록보다 앞선 별도 시도이며 최종 상태가 아니다.
- Claude 매니페스트 검사는 통과했고 기존 author 정보 부재 경고 1건이 있었다. 기존 정적 검사 4개도 다시 통과했다.

이번 배포는 사용자의 명시적 커밋·푸시·배포 요청에 따라 진행했다. 설치 갱신 성공과 실제 모델 호출 성공은 구분하며, 이번에는 두 플랫폼의 호출 계약과 설치본 반영을 확인했다.
