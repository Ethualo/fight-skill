# fight-clarify

모호한 지시를 양극단 두 해석으로 벌려 명세 공백을 드러낸다. **병렬** 2회 호출.

목적이 반박이 아니라 해석 공간을 벌리는 것이므로 두 에이전트는 서로 검증하지 않는다.

이 스킬은 Claude Code와 Codex 양쪽에서 동작한다. 프로토콜(축 선정, 프롬프트, 비교 규칙)은 플랫폼과 무관하게 동일하고, **호출 계약만** 아래처럼 플랫폼별로 다르다.

이 문서는 실행 오케스트레이터가 아니라 호스트 에이전트가 따를 프롬프트 프로토콜이다. 호출 수·순서·병렬성·모델 선택을 플러그인 파일이 자동 검증하거나 강제하지는 않는다.

## 공통 규칙

- 서브에이전트는 파일을 직접 수정하지 않는다. 해석과 제안만 한다.
- 외부 provider·CLI·MCP를 호출하지 않는다.
- 두 서브에이전트 결과 모두 올 때까지 기다린다. 반복 polling은 피한다.

## 해석자 컨텍스트 수집과 상한

- fight-audit의 "제안자 컨텍스트 수집과 상한" 절과 동일한 상한을 따른다.
- 한도를 넘으면 우선순위가 낮은 파일은 경로와 생략 사유만 남긴다. 조용히 초과하지 않는다.

## 1단계 — 애매함 축 선정

지시에서 가장 큰 애매함 축 하나를 뽑고 양극단을 정한다.

```
"로그인 개선해줘"   축=범위   A=최소(기존 폼 UX만)      B=최대(인증 방식 재설계)
"캐시 추가해줘"     축=계층   A=앱 레벨 메모이제이션     B=인프라 레벨 Redis
"에러 처리 좀 해줘" 축=대상   A=사용자 노출 메시지만     B=내부 복구·재시도까지
```

축은 **하나만** 고른다. 두 개 이상 벌리면 두 안의 차이가 어느 축에서 왔는지 읽을 수 없다.

Claude Code의 `AskUserQuestion`에서 "모르겠음 — 양극단 두 안 보여줘"로 진입한 경우 이 단계를 건너뛴다. Codex에서 사용자가 같은 의도로 스킬을 직접 호출한 경우에도 동일하게 적용한다. 네가 물으려던 질문이 곧 애매함 축이고, 그 선택지의 양끝이 극단이다. 선택지가 셋 이상이면 가장 멀리 떨어진 두 개를 극단으로 쓰고, 나머지는 3단계 비교에서 다시 올린다.

## 2단계 — 병렬 dispatch

두 서브에이전트를 **같은 메시지에서** 호출한다. 순차로 돌리지 마라.

**Claude Code:** `Agent` 툴 2회. `subagent_type: general-purpose`, `model: sonnet`, `run_in_background: false`.

**Codex:** subagent spawn 도구 2회. `model: gpt-5.6-luna`, reasoning effort `max`, `fork_context: false`. 지정 모델을 쓸 수 없으면 다른 모델로 조용히 대체하지 말고 유저에게 중단 사유를 알린다.

모델 지정은 호스트에 대한 요청이다. 조직 정책·모델 가용성으로 대체되거나 요청값을 쓸 수 없으면, 메인은 실제 설정을 밝히고 이 프로토콜 호출을 중단한다. 플러그인만으로 대체를 감지·차단할 수는 없다.

각 프롬프트 템플릿. 방향만 바꿔 두 번 쓴다.

````
너는 해석자다. 아래 지시를 지정된 방향으로 해석해 구체안을 낸다.

## 지시
{유저 지시 원문 그대로}

## 배정된 해석
축: {축 이름}
방향: {극단 A 또는 극단 B의 서술}

이 방향으로 해석을 확정한다. 중간을 취하거나 다른 방향을 제안하지 마라.
배정이 과하다고 느껴져도 그 방향으로 끝까지 간다. 극단을 실물로 보는 것이 목적이다.

## 컨텍스트
{관련 파일 경로와 핵심 코드}

## 규칙
- 배정된 축 밖의 애매함은 `[가정]` 태그를 붙이고 네 판단으로 메운다. 각 가정의 지시·코드 근거를 밝히고, 없으면 `근거: 없음`으로 쓴다.
- 구현안은 어느 파일을 어떻게 바꾸는지까지 내려간다.
- 이 해석의 대가가 무엇인지 한 줄로 밝힌다.
- 파일은 수정하지 않는다.

## 출력 형식
### 안
{구현안}

### 가정
- `[가정]` {내용} — 근거: {지시·파일:줄 또는 없음}

### 이 해석의 대가
{한 줄}
````

## 3단계 — 메인 비교

1. **두 안이 일치해도 근거를 확인한다.** 지시·코드로 뒷받침된 일치점만 확정하고 재질문하지 않는다. 근거 없는 공통 가정은 미확정으로 남긴다. 두 에이전트의 동의 자체는 근거가 아니다.
2. **갈린 부분과 결과에 영향을 주는 근거 없는 가정**을 메인 스레드의 사용자 질문으로 올린다. Claude Code는 `AskUserQuestion`, Codex는 대화 응답을 사용한다. 선택지는 추상적 서술이 아니라 두 안의 실물 차이로 쓴다.
3. 이 스킬이 진행 중인 모든 질문에는 "모르겠음 — 양극단 두 안 보여줘" 재진입 옵션을 붙이지 않는다. 사용자가 답을 모르면 미확정 항목과 필요한 정보를 남기고 종료한다. 같은 질문으로 서브에이전트를 다시 호출하지 않는다.
4. 유저 선택 후 확정된 지시문을 재작성한다. 선택하지 않은 가정은 확정문에 섞지 않고 미확정 항목으로 따로 출력한 뒤 스킬을 끝낸다.
5. `fight-audit`을 자동으로 이어 호출하지 않는다. 필요하면 유저가 부른다.

**두 안이 비슷하게 나온 경우**: 축을 잘못 뽑은 것이다. 다른 축으로 재시도하지 말고 유저에게 직접 묻는다. 재시도는 호출 비용만 두 배로 만든다.
